A model writing `tests/` is allowed to write tests that make itself pass.
The producer and evaluator should be separated wherever possible.

## The core problem

When an agent writes both the code and the tests, the tests have low
[independence](framework.html). The agent can write tests that pass on its
implementation regardless of correctness. This is the fundamental weakness of
[example-based tests](example-based-tests.html) and [line
coverage](line-coverage.html) when applied to AI-generated code.

## Solutions

- **Separate authors**: human writes tests, agent writes code (or vice versa)
- **Separate models**: different agents write code and tests
- **Separate time**: tests written before the implementation (TDD-style),
  so the test author can't tailor tests to the implementation
- **Separate origin**: tests generated by a different tool — a
  [property-based](metamorphic-testing.html) generator, a
  [fuzzer](fuzzing.html), or a [mutation tester](mutation-testing.html) —
  where the *sensor itself* generates the adversarial input, not the code
  author
- **Separate org**: external audit, red team, or a third-party conformance
  suite
- **Use independence-strong sensors**: [mutation testing](mutation-testing.html)
  and [fuzzing](fuzzing.html) have higher independence because the *sensor
  itself* generates the adversarial input, not the code author

## In practice

The principle cashes out as a check on who authored the artifacts that
grade a change. A concrete reading compares authors across the
pipeline:

| Artifact | Author | Independence |
|----------|--------|--------------|
| implementation diff | agent A, session 412 | n/a, the subject |
| unit tests covering the diff | agent A, session 412 | compromised |
| integration suite | human, written 2026-03-11 | independent |
| review verdict | agent B, different model family | independent |
| mutation score | generated by the tooling | independent |

The second row is the finding: the agent being tested wrote the tests.
Every verdict downstream of that row inherits the weakness.

Reading it well:

- **Audit authorship, not just verdicts.** Green tests from a
  compromised author are not evidence. Ask who, or which session,
  produced each artifact before trusting its result.
- **Time counts as separation.** Tests written before the
  implementation cannot be tailored to it. Tests authored minutes
  after the code they cover, in the same session, are a paraphrase of
  the code.
- **Prefer sensors that grade themselves.** [Mutation
  testing](mutation-testing.html) and [fuzzing](fuzzing.html)
  generate their own adversarial input, so there is no author to
  compromise. Where separation is hard to arrange, reach for those.

## How it gets gamed

Separation is a property of who wrote what, and that property is easy
to fake:

- **Same-session tests.** The agent writes the implementation, then
  writes the tests in the same session with the implementation in
  context. The tests are a paraphrase of the code, and they pass by
  construction.
- **Self-review under a new name.** The reviewing "agent" receives the
  producer's diff and the producer's rationale in one prompt. The
  separation is nominal; the context is shared.
- **Teaching to the mutation.** If the same agent sees the mutation
  tester's failures and then edits the suite, it can write tests that
  kill every mutant by asserting on the current behavior, including
  the wrong parts. The score rises; correctness does not.
- **Waiver as policy.** "The agent may write tests when no human is
  available" quietly becomes the default state, and the separation
  exists only on paper.

The meta-signal is authorship metadata per artifact: which session
wrote the code, which wrote the tests, which reviewed. If the metadata
is missing, assume the worst case. Separation you cannot verify is
separation you do not have.

## Response playbook

When an audit finds the producer grading itself:

1. **Re-author the compromised artifact.** If the producer wrote the
   tests, the tests do not count. Have a different session, model, or
   human write them from the specification, not from the
   implementation.
2. **Re-run the affected gates from the re-authored artifact.** A
   green suite that ran against compromised tests is not evidence.
   The verdict only regains meaning once the inputs are independent.
3. **Record authorship metadata for every artifact.** Which session
   wrote the code, which wrote the tests, which reviewed. Without
   this record, separation is a claim you cannot check.
4. **Move the check into the pipeline.** Authorship separation is
   easy to violate and easy to forget. Make the pipeline refuse to
   run a gate whose inputs were authored by the subject of the gate.
5. **Prefer self-grading sensors where separation is hard.** If the
   workflow cannot reliably keep producer and evaluator apart, lean
   on [mutation testing](mutation-testing.html) and
   [fuzzing](fuzzing.html), which generate their own adversarial
   input. The sensor grades the code; there is no author to
   compromise.

## What it cannot detect

Producer-evaluator separation is a principle, not a sensor itself. It must
be operationalized through specific sensors that have structural independence
built in.
